# AI Agent 시스템 아키텍처 적합성·정합성 셀프체크

Gottweis et al. (2026)의 Co-Scientist 논문에서 도출한 상위 설계 원칙을 참조하여, 교수님별 AI Agent 시스템의 **실제 목적·아키텍처 유형·도메인·설계 의도에 맞게** 제출 패키지를 점검하는 Streamlit 도구임.

이 도구는 Co-Scientist형 멀티에이전트 구조를 유일한 정답으로 보지 않음. 여러 아키텍처 이미지/PDF와 여러 기능별 MD 파일을 통합 분석하고, 평가 프로파일·파일 간 정합성·AI 판단 근거·설계 의도·공정성 해석과 **프로젝트 맞춤 AI Agent·운영 설계 권고**를 포함한 결과 PDF를 생성함.

## 1. 평가 원칙

논문 그림의 외형, Agent 수, Supervisor의 존재 여부를 평가하지 않음. 시스템이 업무 목적에 맞는 구조를 선택했고, 그 구조의 역할 또는 처리 단계, 정보·근거 흐름, 검증·대체 통제, 사람의 관여, 최종 결과가 이미지와 MD에서 일관되게 설명되는지를 평가함.

> **의도적으로 사용하지 않은 구조는 미사용 사유와 대체 통제가 명확할 때 감점 사유가 아님.** 예를 들어 근거이론 분석처럼 재현성과 인용 좌표 보존이 중요한 시스템은 동적 Supervisor나 다수 Agent 없이 결정론 파이프라인을 선택할 수 있음. 이때는 Agent 수가 아니라 처리 순서·입력·버전·출처·감사 추적을 평가함.

## 2. 평가 프로파일

모든 프로파일은 100점이지만, 각 점수는 선택한 프로파일 안에서만 해석함. 따라서 멀티에이전트 협업형과 결정론 파이프라인형의 점수를 Agent 수로 비교하지 않음.

| 평가 프로파일 | 적합한 시스템 | 핵심 평가 관점 |
|---|---|---|
| **자동 판별** | 유형이 불명확하거나 초기 점검이 필요한 경우 | 업로드 자료·도메인·설계 의도를 종합해 가장 적합한 프로파일을 선택함 |
| **멀티에이전트 협업형** | 연구보조, 복합 분석, 장기 과제, 협업형 Agent 시스템 | 조정 역할, 전문 Agent 분업, Agent 간 흐름, 피드백, 결과 통합 |
| **결정론·감사가능 파이프라인형** | 근거이론, 질적 연구, 규정 처리, 인용 좌표 보존, 배치 분석 | 고정 처리 순서, 재현성, 출처·버전·파라미터 추적, 감사, 예외 처리 |
| **단일 Agent·도구 워크플로형** | 검색, 요약, 생성, 분류, 추천처럼 한 기능이 중심인 시스템 | 업무 범위, 단일 Agent 책임, Tool 경계, 정보 흐름, 검증·승인 |
| **사람 승인 중심 워크플로형** | 교육, 행정, 상담, 의료, 법무 등 최종 책임자가 필요한 업무 | 역할·책임, 승인·반려, 예외·에스컬레이션, 개인정보, 감사 이력 |
| **혼합·맞춤형** | 둘 이상의 유형이 결합되거나 독특한 설계인 경우 | 설계 선택의 적합성, 구성요소 경계, 흐름·근거·상태, 대체 통제 |

세부 배점과 적용 원칙은 `evaluation_profile_guide.md`를 참고함.

## 3. 평가 전 입력할 내용

평가를 시작하기 전에 아래 네 항목을 입력함. 특히 마지막 두 항목은 ‘특정 구조가 없어서 점수가 낮아지는’ 문제를 방지하는 핵심 정보임.

| 입력 항목 | 작성 예시 |
|---|---|
| 시스템 유형·평가 프로파일 | `결정론·감사가능 파이프라인형` 또는 `자동 판별` |
| 적용 도메인 | `근거이론·질적 연구 분석`, `학사행정`, `교육과정 설계` |
| 핵심 설계 의도 | `동일 입력에서 동일 결과를 보장하고 문장별 인용 좌표를 보존함` |
| 의도적으로 제외한 구조와 사유 | `동적 Supervisor와 다수 Agent는 감사가능성과 재현성을 위해 제외함` |
| 설계 권고 수준 | `핵심 보완안만`, `도메인 맞춤 설계 권고 포함`, `단계별 확장 로드맵 포함` |

## 4. 프로젝트 맞춤 설계 권고

설계 권고는 **평가 점수와 완전히 분리된 발전 제안**임. 권고된 AI Agent, Memory, Tool, 검증 모듈, 운영 통제를 추가하지 않아도 감점하지 않음. 현재 구조를 논문의 외형처럼 바꾸는 대신, 도메인·시스템 유형·핵심 설계 의도·실제 업로드 자료에 근거해 다음을 제시함.

| 권고 구분 | 제공 내용 |
|---|---|
| 유지할 설계 강점 | 현재 설계에서 반드시 보존할 제약, 품질 요건, 통제 방식 |
| 우선 보완안 | 실제 파일에서 확인된 공백 또는 위험에 대한 우선순위·근거·구현 힌트 |
| 조건부·선택적 확장 | 도입 조건이 충족될 때만 고려할 Agent·검증 모듈·Tool·Memory·운영 통제와 트레이드오프 |
| 도입 보류 또는 회피 권고 | 설계 의도·재현성·안전성·책임 구조와 충돌해 도입을 피해야 할 구조 |
| 다음 검증 단계 | 시험·감사·사용자 검토·운영 점검의 완료 기준 |

예를 들어 결정론 파이프라인에는 다수 Agent보다 실행 매니페스트, 인용 좌표 검증, 규칙·프롬프트 버전 고정, 재실행 테스트를 우선 권고함. 반대로 멀티에이전트형에는 역할 중복 제거, 검증 Agent 독립성, Tool 권한, Memory 범위, 종료 조건을 우선 권고함.

## 5. 업로드 파일

### 아키텍처 구성도

여러 개의 `PNG`, `JPG/JPEG`, `PDF` 파일을 업로드할 수 있음. 개요도, 세부 구성도, 데이터 흐름도, Tool/API 연계도를 함께 업로드하면 됨. PDF는 페이지별 이미지로 분석함. 여러 그림은 상호 보완 자료로 해석하며, 동일 구성요소 또는 처리 단계가 서로 모순될 때만 파일 간 불일치로 지적함.

### 기능별 설명 파일

여러 개의 `MD`, `TXT` 파일을 업로드할 수 있음. 시스템 개요, Agent 또는 처리단계별 기능, 데이터·근거, Memory·Tool, 검증·승인·예외 처리를 별도 파일로 제출해도 됨. 이미지 속 구성요소의 이름 또는 ID는 MD의 역할·입력·처리·출력·연결 관계와 대응되어야 함.

## 6. 실행 방법

### 의존성 설치

```bash
pip install -r requirements.txt
```

### API 키 설정

앱 사이드바에 `Anthropic API Key`를 입력하거나, 프로젝트 루트의 `.streamlit/secrets.toml`에 아래처럼 저장함.

```toml
ANTHROPIC_API_KEY = "sk-ant-..."
```

### 실행

```bash
streamlit run app.py
```

## 7. 결과 PDF 구성

평가 완료 뒤 내려받는 `architecture_consistency_report_교수님성함.pdf`에는 아래 내용을 포함함.

1. 제출 교수·소속·평가 일시·평가 모델 정보
2. 적용 평가 프로파일과 적용 도메인
3. 프로파일 선택 근거, 공정성 해석, 설계 의도, 의도적 제외 구조
4. 총점·판정·프로파일별 평가 항목과 AI 판단 근거
5. 실제 업로드한 다중 이미지/PDF·MD 파일 목록
6. 파일 간 불일치 또는 보완 권고
7. 내부 정합성 체크와 파일별 분석 메모
8. 종합 의견과 논문 기반 평가 방법론
9. 프로젝트 맞춤 AI Agent·운영 설계 권고: 유지할 강점, 우선 보완안, 조건부 확장, 도입 보류, 다음 검증 단계

긴 AI 판단 근거, 파일 간 불일치, 수정 권고, 내부 점검 코멘트, 파일별 분석 메모와 종합 의견은 문자 수로 축약하지 않음. 내용이 길면 PDF에서 자동 줄바꿈 및 페이지 분할되어 전체 내용이 출력됨.

## 8. 운영 유의사항

- 실제 구현하지 않은 Agent, Memory, API, Feedback Loop를 점수 목적만으로 추가하지 않음.
- 다수 Agent나 Supervisor가 없을 때는, 해당 부재를 숨기지 않고 설계 목적·대체 통제·예외 처리 방식을 MD에 명시함.
- 결정론 파이프라인은 입력·문서·규칙·모델·프롬프트 버전, 처리 순서, 출처 좌표, 감사 로그를 설명하는 것이 중요함.
- 사람 승인형 시스템은 승인권자·승인 기준·반려·예외·에스컬레이션·기록 위치를 설명하는 것이 중요함.
- 원본 아키텍처 구성도는 보존하고, 수정본에서만 도식 표기·용어·화살표·범례를 통일함.
- AI 자동 점수는 1차 보조 결과임. 최종 점수와 총평은 멘토 또는 담당자가 검토·수정한 뒤 확정함.
- 설계 권고는 개발 우선순위를 돕는 제안이며, 추천 Agent 또는 Tool의 도입 여부는 교수님 프로젝트의 목적·예산·운영 환경·책임 구조에 따라 멘토와 담당자가 결정함.

## 9. 기준 논문

Gottweis, J. et al. (2026). *Accelerating scientific discovery with Co-Scientist*. Nature. DOI: [10.1038/s41586-026-10644-y](https://doi.org/10.1038/s41586-026-10644-y).

Co-Scientist는 멀티에이전트 협업형의 참조 사례임. 본 도구는 이를 모든 시스템의 구조 규격으로 사용하지 않고, 목표 명확성·단계 또는 역할 분리·정보 및 근거 추적·검증 또는 대체 통제·사람의 책임 있는 관여·결과 명확성이라는 상위 원칙으로 재해석해 적용함.
